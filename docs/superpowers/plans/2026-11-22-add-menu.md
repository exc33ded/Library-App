# Add-Menu (the "+" popup) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. One task, worker = Claude subagent on **Sonnet** (UI judgment + compile-time API checks). Worker does not commit; the main session reviews, verifies on the emulator and commits. Never give the worker `local.properties` or `docs/Books-Photo/`.

**Goal:** Replace the plain `DropdownMenu` behind the bottom-bar "+" button with a polished, animated add menu: dimmed backdrop, action pills that spring up one after another from the button, the "+" morphing into a "×". No default Material dropdown anywhere in this flow.

**Why custom (not `FloatingActionButtonMenu`):** the "+" lives inside the `NavigationBar` slot; the Expressive `FloatingActionButtonMenu` lays its items out around its own button and would be clipped/mis-sized there. So the toggle FAB stays in the bar and the menu is an overlay above the content.

**Tech:** Compose Material 3 Expressive (`ToggleFloatingActionButton`, `MaterialTheme.motionScheme`), `AnimatedVisibility`, `BackHandler`.

- [ ] **Step 1: Create `ui/nav/AddMenu.kt`** with this design (write idiomatic code; the structure and values below are the contract):

```kotlin
import androidx.activity.compose.BackHandler

```

  1. `@Composable fun AddMenuOverlay(visible: Boolean, actions: List<AddAction>, onDismiss: () -> Unit, modifier: Modifier = Modifier)`. A full-size `Box`. Compose it only while needed (keep it in composition while `visible` OR while the exit animation runs — simplest: always compose it but use `AnimatedVisibility` for the scrim and each item, and make the scrim non-clickable when `!visible`).
  2. **Scrim:** `AnimatedVisibility(visible, enter = fadeIn(effectsSpec), exit = fadeOut(effectsSpec))` around a `Box(Modifier.fillMaxSize().background(MaterialTheme.colorScheme.scrim.copy(alpha = 0.5f)).clickable(interactionSource = remember { MutableInteractionSource() }, indication = null, onClick = onDismiss))`.
  3. **Items:** a `Column(Modifier.align(Alignment.BottomCenter).padding(bottom = 20.dp), verticalArrangement = Arrangement.spacedBy(12.dp), horizontalAlignment = Alignment.CenterHorizontally)`. For each action (index `i` of `n`), wrap a pill in `AnimatedVisibility(visible, enter = <staggered>, exit = fadeOut(effectsSpec) + scaleOut(targetScale = 0.9f))`. The **item nearest the button (the last one in the list) appears first**: delay = `(n - 1 - i) * 40` ms. Enter = `fadeIn(tween(180, delayMillis = delay)) + scaleIn(spatialSpecWithDelay, initialScale = 0.8f, transformOrigin = TransformOrigin(0.5f, 1f)) + slideInVertically(spatialSpecWithDelay) { it / 2 }`. Use `MaterialTheme.motionScheme.defaultSpatialSpec<…>()` / `fastEffectsSpec<Float>()` for the springs where the types allow, and wrap them with the delay by building the spec with `tween`/`spring` + `delayMillis` as the API allows (if a motion-scheme spec cannot take a delay, use `tween(durationMillis = 320, delayMillis = delay, easing = FastOutSlowInEasing)` for that item — the goal is a smooth staggered rise, not exact spring parameters).
  4. **Pill:** `Surface(onClick = { action.onClick() }, shape = RoundedCornerShape(28.dp), color = MaterialTheme.colorScheme.secondaryContainer, contentColor = MaterialTheme.colorScheme.onSecondaryContainer, shadowElevation = 6.dp, tonalElevation = 2.dp)` containing `Row(Modifier.height(56.dp).padding(horizontal = 20.dp), verticalAlignment = Alignment.CenterVertically, horizontalArrangement = Arrangement.spacedBy(12.dp))` with `Icon(action.icon, null, tint = MaterialTheme.colorScheme.primary)` and `Text(action.label, style = MaterialTheme.typography.titleMedium)`.
  5. `BackHandler(enabled = visible, onBack = onDismiss)`.
  6. Add `@Composable fun AddToggleButton(expanded: Boolean, onToggle: () -> Unit, modifier: Modifier = Modifier)`: a `ToggleFloatingActionButton(checked = expanded, onCheckedChange = { onToggle() }, modifier = modifier.semantics { contentDescription = if (expanded) "Close add menu" else "Add book" })` whose content is the Expressive pattern: `val icon by remember { derivedStateOf { if (checkedProgress > 0.5f) Icons.Filled.Close else Icons.Filled.Add } }; Icon(icon, contentDescription = null, modifier = Modifier.animateIcon({ checkedProgress }))` (`checkedProgress` comes from `ToggleFloatingActionButtonScope`). Add `@OptIn(ExperimentalMaterial3ExpressiveApi::class)` where needed. If `animateIcon` does not resolve, drop that modifier and instead rotate the icon with `Modifier.graphicsLayer { rotationZ = checkedProgress * 90f }` (read inside the lambda).

- [ ] **Step 2: Wire into `AppNav.kt`.**
  1. Add state near `tabDirection`: `var addMenuOpen by remember { mutableStateOf(false) }`.
  2. `BottomBar` gets two new parameters `menuOpen: Boolean` and `onMenuToggle: () -> Unit`, and its centre slot becomes `Box(Modifier.weight(1f), contentAlignment = Alignment.Center) { AddToggleButton(menuOpen, onMenuToggle) }`. **Delete** the old `FloatingActionButton`, the `var menu` state and the entire `DropdownMenu { … }` block, and the now-unused icon/menu imports (`DropdownMenu`, `DropdownMenuItem`, `FloatingActionButton`, and any icon import no longer referenced in this file — the icons move to the actions list below).
  3. Build the actions once in `AppNav` (they close the menu first, then act):
     ```kotlin
     val addActions = listOf(
         AddAction(Icons.Filled.PhotoCamera, "Photo of cover") { addMenuOpen = false; launchCamera() },
         AddAction(Icons.Filled.PhotoLibrary, "Import from gallery") { addMenuOpen = false; pickPhotos.launch(PickVisualMediaRequest(ActivityResultContracts.PickVisualMedia.ImageOnly)) },
         AddAction(Icons.Filled.QrCodeScanner, "Scan ISBN") { addMenuOpen = false; scanIsbn() },
         AddAction(Icons.Filled.Search, "Search online") { addMenuOpen = false; push(FindBookKey()) },
         AddAction(Icons.Filled.Edit, "Enter manually") { addMenuOpen = false; push(BookEditKey()) },
     )
     ```
     (the order in the list is top-to-bottom on screen; "Enter manually" is nearest the button).
  4. Pass `menuOpen = addMenuOpen, onMenuToggle = { addMenuOpen = !addMenuOpen }` to `BottomBar`. In the tab `onSelect` lambda set `addMenuOpen = false` before switching.
  5. In the `Scaffold` content lambda, wrap the existing `NavDisplay(...)` in a `Box(Modifier.padding(padding))` (move the `padding` from the NavDisplay modifier to the Box) and add `AddMenuOverlay(visible = addMenuOpen && top in topLevelKeys, actions = addActions, onDismiss = { addMenuOpen = false })` as the box's last child, so the overlay sits above the page content but below the bottom bar (the toggle button stays visible and clickable).
  6. Everything else in `AppNav` stays as is (tab slide/fade, `push`, entries).
