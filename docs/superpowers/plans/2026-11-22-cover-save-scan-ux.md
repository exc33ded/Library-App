**A. Cover editing**
1. `CoverStore`: add `suspend fun saveFromUri(uri: Uri, bookId: String): String?` that decodes the image with `ImageDecoder` (it applies EXIF rotation; `ALLOCATOR_SOFTWARE`), downsizes so the longest edge is at most 1200 px, writes JPEG quality 88 to `filesDir/covers/{bookId}.pending.jpg` (create the folder) and returns the absolute path, or null on failure; plus `fun pendingFile(bookId: String): File` and `fun clearPending(bookId: String)`. Add a pure helper `coverTargetSize(w: Int, h: Int, max: Int = 1200): Pair<Int, Int>` (never upscales, keeps aspect ratio) with a unit test in `metadata/CoverSizeTest.kt` (e.g. 4096x3072 -> 1200x900, 800x600 stays, 3000x4000 -> 900x1200).
2. `EditUiState`: add `coverMode: CoverMode` where `enum class CoverMode { KEEP, PICKED, REMOVED }` (default KEEP) and keep `coverPreview` as the displayed image. ViewModel: `fun setCoverFromUri(uri: Uri)` (saves via `CoverStore.saveFromUri`, sets `coverPreview = pendingPath`, `coverMode = PICKED`), `fun removeCover()` (`coverPreview = null`, `coverMode = REMOVED`), and `fun useOnlineCover()` (only offered when `prefill?.coverUrl != null`: `coverPreview = prefill.coverUrl`, `coverMode = KEEP`). In `save()`: PICKED -> copy the pending file to `covers/{id}.jpg` (overwrite) and use that path, then delete the pending file; REMOVED -> `coverPath = null` (and delete `covers/{id}.jpg` if it exists); KEEP -> today's behaviour (remote URL download, else import photo, else the original path). Make sure cancelling the edit never changes the stored cover (only the pending file is written before Save).
3. `BookEditScreen`: replace the small `BookCover(...)` at the top with a tappable cover area (cover preview, or a dashed rounded placeholder with a camera icon and "Add cover" when none) plus an **"Edit cover"** / **"Add cover"** `FilledTonalButton`. Tapping either opens a `ModalBottomSheet` with large tappable rows (icon + label): "Choose from gallery" (`ActivityResultContracts.PickVisualMedia`, image only), "Take a photo" (`ActivityResultContracts.TakePicture` into `File(context.filesDir, "camera/{timestamp}.jpg")` via `FileProvider.getUriForFile(context, "${context.packageName}.files", file)` exactly like `AppNav.launchCamera`; the camera needs no extra permission with `TakePicture`), "Remove cover" (only when a cover is shown) and "Use the online cover" (only when `prefill?.coverUrl != null` and the current preview differs). Sheet rows close the sheet first. Works for manual add, editing an existing book, and the import "Edit" flow (all use this screen).

**B. Save feedback and transition**

States driven by the ViewModel: Idle ("Save", save icon), Saving (small `CircularProgressIndicator` + "Saving…", disabled), Saved (check icon + "Saved", container colour animates to `tertiaryContainer`/`primaryContainer` with `animateColorAsState`). Use `AnimatedContent` (fade + scale, short tweens) to swap the label/icon. Add `saved: Boolean` handling: the existing `savedId` effect should now wait about 600 ms in the Saved state before leaving, then call a new `onSaved(title: String)` callback (keep `onDone` for Back).
5. `AppNav`: `entry<BookEditKey>` gets `onSaved = { title -> backStack.removeLastOrNull(); scope.launch { snackbar.showSnackbar("Saved “$title”") } }` and a sheet-like transition via entry metadata: on push `slideInVertically(tween(260, easing = FastOutSlowInEasing)) { it / 6 } + fadeIn(tween(200))` together with the usual fade-out of the previous screen; on pop (`NavDisplay.PopTransitionKey`) the edit screen slides down and fades (`slideOutVertically(tween(240, easing = FastOutLinearInEasing)) { it / 6 } + fadeOut(tween(160))`) while the previous screen fades in. **C. Scanner robustness** (the search-bar scan icon and the "+" menu action must share one flow)
